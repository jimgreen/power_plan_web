# 规划求解程序说明

本文档说明“规划求解”后台程序的当前实现，包括入口流程、输入数据、优化变量、目标函数、约束条件和输出结果。

## 1. 程序位置与调用链

规划求解的核心求解程序位于：

- `plan_optimizer.py`
- `dispatch_milp.py`：规划求解与方案评估共享的 MILP 建模工具和公共约束
- `milp_solver.py`：Gurobi / CPLEX / MOSEK / SciPy 求解器适配器

页面点击“规划求解”后，后端调用链为：

1. `server.py` 中 `/api/optimization/control` 接收 `start` 指令。
2. `OptimizationRuntime.apply("start")` 创建后台线程。
3. 后台线程执行 `OptimizationRuntime._run_optimization()`。
4. 程序读取当前方案参数：`PLANNING_STORE.read_scheme(scheme)`。
5. 调用 `plan_optimizer.run_optimization(scheme_payload)`。
6. 求解完成后写入同目录默认结果文件：`opt_results.xlsx`。

规划求解与方案评估使用独立运行时：

- 规划求解：`OptimizationRuntime`
- 方案评估：`EvaluationRuntime`

## 2. 输入数据

### 2.1 时序数据

规划求解默认要求 8760 点时序数据。

每小时读取以下字段：

- `wind_speed`：风速
- `solar_irradiance`：太阳辐射
- `temperature`：环境温度，仅输出曲线使用
- `load`：负荷功率
- `datetime`：时间标签
- `hour_index`：小时序号

实际用于优化的负荷为：

```text
Load_t = load_t
```

即直接使用 8760 时序数据中的负荷功率。

### 2.2 规划参数

当前规划求解 MILP 使用以下全局规划参数：

- `diesel_price`：柴油价格，单位：万元/吨
- `green_power_ratio_lower`：绿色电量占比下限，取值范围 0 到 1
- `optimization_time_limit_minutes`：规划求解时间上限，单位：分钟，默认 60，输入范围 10 到 120
- `initial_storage_soc_ratio`：初始电储 SOC，默认 0.5，取值范围 0 到 1
- `initial_hydrogen_storage_ratio`：初始氢储 SOC，默认 0.5，取值范围 0 到 1
- `post_disturbance_power_balance_enabled`：是否考虑扰动后平衡约束，取值 0/1，默认 1
- `load_up_disturbance_factor`：负荷向上扰动系数，取值范围 0 到 0.5
- `load_down_disturbance_factor`：负荷向下扰动系数，取值范围 0 到 0.5
- `renewable_down_disturbance_factor`：新能源向下扰动系数，取值范围 0 到 0.5

注意：`设计使用年限(年)` 已从“规划参数”移除。设备寿命按各设备表中的 `design_life_years` 分别读取。

### 2.3 设备参数

优化支持以下设备表：

| 设备表 | 设备类型 | 容量字段 | 单位 |
| --- | --- | --- | --- |
| `diesel_generators` | 柴发 | `capacity` | kW |
| `wind_turbines` | 风机 | `capacity` | kW |
| `photovoltaics` | 光伏 | `capacity` | kW |
| `storage_pcs` | 储能PCS | `power_capacity` | kW |
| `storage_battery_packs` | 储能电池组 | `battery_capacity` | kWh |
| `hydrogen_electrolyzers` | 电制氢 | `power_capacity` | kW |
| `hydrogen_tanks` | 储氢罐 | `hydrogen_tank_capacity` | Nm3 |
| `fuel_cells` | 燃料电池 | `power_capacity` | kW |

每个设备行均参与建设台数优化，读取：

- `quantity_lower`：建设台数下限
- `quantity_upper`：建设台数上限
- `cost`：成本，单位：万元/台
- `design_life_years`：设计年限，单位：年

柴发额外读取：

- `power_upper`：单台运行功率上限
- `power_lower`：单台运行功率下限
- `fuel_rate`：油耗率，单位：kg/kWh

风机额外读取：

- `cut_in_wind_speed`：切入风速
- `cut_out_wind_speed`：切出风速

储能 PCS 额外读取：

- `storage_charge_efficiency`：充电效率，默认 0.95，取值范围 0 到 1 且必须大于 0
- `storage_discharge_efficiency`：放电效率，默认 0.95，取值范围 0 到 1 且必须大于 0
- `is_grid_forming`：是否构网，取值 1/0，默认 0

储能电池组额外读取：

- `soc_upper`：SOC 上限，取值范围 0 到 1，默认 0.9
- `soc_lower`：SOC 下限，取值范围 0 到 1，默认 0.1

说明：

- 储能电池组的 SOC 上下限会作为运行约束的阈值使用。
- 当前程序将各行储能电池组的 SOC 上下限汇总成一个系统级阈值，用来控制统一的储能 SOC 状态。

电制氢额外读取：

- `power_lower`：单台制氢功率下限
- `electric_to_hydrogen_efficiency`：电-氢效率，单位：Nm3/kWh

燃料电池额外读取：

- `hydrogen_to_electric_efficiency`：氢-电效率，单位：kWh/Nm3

## 3. 优化问题类型

当前规划求解建立的是混合整数线性规划问题，即 MILP。

求解器调用：

```text
milp_solver.solve_milp()
```

规划求解和方案评估默认显式传入 `options["solver"] = "mosek"`，调用 MOSEK 原生 Task API。`milp_solver.solve_milp()` 本身仍保留 `auto` 模式，供测试或手工调用时按 Gurobi -> CPLEX -> MOSEK -> SciPy 顺序回退。

可通过 `options["solver"]` 显式指定求解器：

```text
auto   = Gurobi -> CPLEX -> MOSEK -> SciPy
gurobi = 只调用 Gurobi
cplex  = 只调用 CPLEX，cplx 为别名
mosek  = 只调用 MOSEK，msk 为别名
scipy  = 只调用 scipy.optimize.milp，highs 为别名
```

主要求解参数：

```text
time_limit = 从规划参数 optimization_time_limit_minutes 读取后乘以 60 秒，默认 3600 秒
mip_rel_gap = 0.01
```

如果求解器未声明最优，但返回了可行解，程序会保留该可行解并输出警告日志。

## 4. 下标与符号

本文档使用以下下标：

- `t`：小时，`t = 1...8760`
- `i`：设备表中的设备行
- `u`：历史版本中用于表示同一设备行下单台设备序号；当前模型已尽量改为台数级整数变量，不再对风光、柴发、电制氢、构网储能按单台展开运行变量。

设备建设台数：

- `q_dg_i`：第 `i` 行柴发建设台数
- `q_w_i`：第 `i` 行风机建设台数
- `q_pv_i`：第 `i` 行光伏建设台数
- `q_pcs_i`：第 `i` 行储能 PCS 建设台数
- `q_bat_i`：第 `i` 行储能电池组建设台数
- `q_el_i`：第 `i` 行电制氢建设台数
- `q_ht_i`：第 `i` 行储氢罐建设台数
- `q_fc_i`：第 `i` 行燃料电池建设台数

## 6. 目标函数

主目标函数为：

```text
minimize  年均建设成本 + 年柴油成本
```

其中：

```text
年均建设成本 = sum_i(q_i * cost_i / design_life_years_i)
```

单位：万元。

```text
年柴油消耗量 = sum_t sum_i(diesel_power_t_i * fuel_rate_i / 1000)
```

单位：吨。

```text
年柴油成本 = 年柴油消耗量 * diesel_price
```

单位：万元。

因此主目标可写为：

```text
minimize
  sum_i(q_i * cost_i / design_life_years_i)
  + diesel_price * sum_t sum_i(diesel_power_t_i * fuel_rate_i / 1000)
```

### 6.1 辅助惩罚项

为保证模型可行性并减少无意义动作，程序还在求解器目标中加入了辅助惩罚项：

| 惩罚项 | 作用 |
| --- | --- |
| `LOAD_SHED_PENALTY_COST * unmet_load_t` | 大惩罚，尽量避免切负荷 |
| `DIESEL_ON_COUNT_PENALTY * diesel_on_count_t_i` | 很小惩罚，减少无意义柴发开机 |
| `ELECTROLYZER_ON_COUNT_PENALTY * electrolyzer_on_count_t_i` | 很小惩罚，减少无意义制氢开机 |

这些惩罚项用于求解稳定性和结果择优，不计入输出的 `年总成本`。输出成本只统计：

弃电功率、储能充放电功率、电制氢功率、燃料电池功率和构网储能开机变量不再附加循环/弃电小惩罚；它们只通过物理约束、建设成本、柴油成本、切负荷惩罚和启停惩罚间接参与择优。

```text
年总成本 = 年均建设成本 + 年柴油成本
```

### 6.2 启动前快速可行性预检查

规划求解和方案评估在真正启动子进程、调用 MILP 求解器之前，都会先执行一组快速可行性预检查。预检查逻辑集中在 `calculation_precheck.py` 中：

| 调用入口 | 使用场景 | 说明 |
| --- | --- | --- |
| `validate_optimization_fast_feasibility(scheme_payload)` | 规划求解 | 直接使用方案参数中的设备数量上下限进行检查。 |
| `validate_evaluation_fast_feasibility(scheme_payload, planning_result_rows)` | 方案评估 | 先把当前结果文件中的“设计台数”转换为固定数量上下限，再复用同一套检查逻辑。 |

预检查只判断“必然不可行”的简单场景，用来提前给出中文错误并避免无意义排队或求解。它不是完整可行性证明；通过预检查后，仍需由 MILP 求解器检查全部约束。

当前预检查包括：

| 序号 | 检查项 | 触发条件 | 处理方式 |
| --- | --- | --- | --- |
| 1 | 绿电比例要求下无风光建设能力 | `绿色电量占比下限 > 0`，且风机可建设容量为 0、光伏可建设容量为 0。规划求解使用数量上限判断；方案评估使用当前结果中的固定设计台数判断。 | 直接报错：风机和光伏均为 0，无法满足绿电比例约束。 |
| 2 | 年度风光最大可发电量不足 | `风机最大可发电量 + 光伏最大可发电量 < 负荷总电量 * 绿色电量占比下限`。 | 直接报错，并给出风光最大可发电量、负荷电量、可达到占比和要求占比。 |
| 3 | 单小时最大供电功率不足 | 任一小时满足 `风机最大可发功率 + 光伏最大可发功率 + 柴发最大可发功率 < 负荷功率`。 | 直接报错，并指出第几个小时、最大供电功率和负荷功率。 |
| 4 | 储氢自损耗无法补偿 | 初始氢储 SOC 大于 0，存在储氢罐数量下限或固定台数大于 0 且自损耗率大于 0，但电制氢数量上限或固定台数为 0。 | 直接报错：模型要求 8760 点期末氢储等于初始氢储，自损耗无法补偿。 |
| 5 | 电储自损耗无法补偿 | 初始电储 SOC 大于 0，存在储能电池数量下限或固定台数大于 0 且自损耗率大于 0，但储能 PCS 数量上限或固定台数为 0。 | 直接报错：模型要求日末电储等于初始电储，自损耗无法补偿。 |

预检查中使用的最大可发计算与优化模型保持一致：

```text
风机最大可发功率_t = sum_i(quantity_upper_i * wind_generation(wind_speed_t, capacity_i, wind_row_i))
光伏最大可发功率_t = sum_i(quantity_upper_i * capacity_i * solar_irradiance_t / 1000)
柴发最大可发功率 = sum_i(quantity_upper_i * power_upper_i)
```

其中方案评估会先将 `quantity_upper_i` 固定为当前结果文件中的设计台数，因此同一公式同时适用于规划求解和方案评估。

## 7. 约束条件

### 7.1 建设台数上下限

对每个设备行：

```text
quantity_lower_i <= q_i <= quantity_upper_i
q_i 为整数
```

### 7.2 每小时功率平衡

对每个小时 `t`：

```text
sum_i(diesel_power_t_i)
+ wind_power_t
+ pv_power_t
+ storage_discharge_t
+ sum_i(fuel_cell_power_t_i)
+ unmet_load_t
- storage_charge_t
- sum_i(electrolyzer_power_t_i)
= Load_t
```

其中：

```text
Load_t = 时序负荷_t
```

`unmet_load_t` 是切负荷变量，允许存在，但目标函数中有大惩罚。

### 7.3 风电出力和弃风约束

程序先按风速和风机参数计算每台风机在小时 `t` 的最大可发功率：

```text
wind_available_per_unit_t_i
```

当前计算公式为分段近似功率曲线：

```text
v_t = wind_speed_t
C_i = capacity_i
v_in_i = cut_in_wind_speed_i
v_out_i = cut_out_wind_speed_i
v_rated_i = max(v_in_i + 0.1, rated_wind_speed_i)
```

```text
wind_available_per_unit_t_i =
  0,                                      v_t < v_in_i 或 v_t >= v_out_i
  C_i,                                    v_t >= v_rated_i
  C_i * ((v_t - v_in_i) / (v_rated_i - v_in_i))^3, 其他情况
```

第 `t` 小时风力最大可发为：

```text
wind_available_t = sum_i(q_w_i * wind_available_per_unit_t_i)
```

由于 `q_w_i` 是整数优化变量，程序不会用自由聚合弃风变量任意分摊弃电，而是引入行级乘积变量来表达建设台数和统一弃电率的乘积：

```text
z_w_t_i = renewable_curtailment_product_t_w_i
```

为保证风机和光伏在同一小时采用同一个弃电率，定义：

```text
0 <= renewable_curtailment_rate_t <= 1
```

表示：

```text
z_w_t_i = q_w_i * renewable_curtailment_rate_t
```

该乘积通过以下线性约束实现：

```text
z_w_t_i <= quantity_upper_w_i * renewable_curtailment_rate_t
z_w_t_i <= q_w_i
z_w_t_i >= q_w_i + quantity_upper_w_i * renewable_curtailment_rate_t - quantity_upper_w_i
0 <= z_w_t_i <= quantity_upper_w_i
```

风电聚合出力和弃风功率再由行级数量变量汇总：

```text
wind_curtailed_t =
  sum_i(wind_available_per_unit_t_i * z_w_t_i)
```

```text
wind_power_t =
  sum_i(wind_available_per_unit_t_i * (q_w_i - z_w_t_i))
```

等价地仍满足：

```text
wind_power_t + wind_curtailed_t
= sum_i(q_w_i * wind_available_per_unit_t_i)
```

但额外保证所有已建设风机行的弃电比例均等于 `renewable_curtailment_rate_t`。该表达不再为每台风机候选台位引入二进制变量，变量规模与设备行数相关。

因此：

- 风机最大可发量由风速、风机容量、切入风速、额定风速、切出风速和建设台数共同决定。
- 弃风通过 `wind_curtailed_t` 表示，并由每个风机设备行按统一弃电率汇总。

### 7.4 光伏出力和弃光约束

程序按太阳辐射和光伏容量计算每台光伏在小时 `t` 的最大可发功率：

```text
pv_available_per_unit_t_i
```

当前计算公式为辐照度线性近似：

```text
G_t = solar_irradiance_t
C_i = capacity_i
```

```text
pv_available_per_unit_t_i =
  C_i * max(0, G_t) / 1000.0
```

程序实现中还按装机容量 `C_i` 做上限截断，避免异常辐照度导致最大可发超过容量。

第 `t` 小时光伏最大可发为：

```text
pv_available_t = sum_i(q_pv_i * pv_available_per_unit_t_i)
```

光伏与风机使用同一个小时弃电率 `renewable_curtailment_rate_t`。对每个光伏设备行：

```text
z_pv_t_i = q_pv_i * renewable_curtailment_rate_t
```

并同样通过线性化约束实现：

```text
z_pv_t_i <= quantity_upper_pv_i * renewable_curtailment_rate_t
z_pv_t_i <= q_pv_i
z_pv_t_i >= q_pv_i + quantity_upper_pv_i * renewable_curtailment_rate_t - quantity_upper_pv_i
0 <= z_pv_t_i <= quantity_upper_pv_i
```

光伏聚合出力和弃光功率为：

```text
pv_curtailed_t =
  sum_i(pv_available_per_unit_t_i * z_pv_t_i)
```

```text
pv_power_t =
  sum_i(pv_available_per_unit_t_i * (q_pv_i - z_pv_t_i))
```

等价地仍满足：

```text
pv_power_t + pv_curtailed_t
= sum_i(q_pv_i * pv_available_per_unit_t_i)
```

因此：

- 光伏最大可发量由太阳辐射、容量和建设台数共同决定。
- 弃光通过 `pv_curtailed_t` 表示，并由每个光伏设备行按同一个弃电率汇总。
- 同一小时内，所有已建设风机和光伏设备行共用 `renewable_curtailment_rate_t`，即弃电率完全一致。

### 7.5 柴发启停、上下限和台数约束

对每个小时 `t` 和每个柴发行 `i`：

```text
diesel_on_count_t_i <= q_dg_i
```

```text
diesel_power_t_i <= power_upper_i * diesel_on_count_t_i
```

```text
diesel_power_t_i >= power_lower_i * diesel_on_count_t_i
```

含义：

- 柴发开机台数不能超过建设台数。
- 柴发出力受单台功率上限和开机台数限制。
- 柴发开机后必须满足单台功率下限。
- `diesel_on_count_t_i` 是台数级整数变量，程序不再对每台候选柴发分别引入 0/1 变量。

### 7.6 电制氢启停、上下限和台数约束

对每个小时 `t` 和每个电制氢行 `i`：

```text
electrolyzer_on_count_t_i <= q_el_i
```

```text
electrolyzer_power_t_i <= power_capacity_i * electrolyzer_on_count_t_i
```

```text
electrolyzer_power_t_i >= power_lower_i * electrolyzer_on_count_t_i
```

含义：

- 电制氢开机台数不能超过建设台数。
- 电制氢功率受单台容量和开机台数限制。
- 电制氢开机后必须满足制氢功率下限。
- `electrolyzer_on_count_t_i` 是台数级整数变量，程序不再对每台候选电制氢设备分别引入 0/1 变量。

### 7.7 燃料电池出力约束

对每个小时 `t` 和每个燃料电池行 `i`：

```text
fuel_cell_power_t_i <= power_capacity_i * q_fc_i
```

燃料电池出力不能超过已建设燃料电池总容量。

### 7.8 储能 PCS 功率约束

对每个小时 `t`：

```text
storage_charge_t <= sum_i(q_pcs_i * power_capacity_i)
```

```text
storage_discharge_t <= sum_i(q_pcs_i * power_capacity_i)
```

含义：

- 电储能充电功率受储能 PCS 总建设功率限制。
- 电储能放电功率受储能 PCS 总建设功率限制。
- 当储能 PCS 行 `is_grid_forming = 1` 时，对应的在线台数会参与“至少一台柴发或构网储能在线”的约束，以及扰动后平衡的调节能力约束。

### 7.9 电储能充放电互斥约束

程序新增两个二进制变量：

```text
storage_charge_on_t
storage_discharge_on_t
```

对每个小时 `t`：

```text
storage_charge_t <= storage_charge_on_t * sum_i(quantity_upper_pcs_i * power_capacity_i)
```

```text
storage_discharge_t <= storage_discharge_on_t * sum_i(quantity_upper_pcs_i * power_capacity_i)
```

```text
storage_charge_on_t + storage_discharge_on_t <= 1
```

含义：

- 同一小时电储能不能同时充电和放电。
- 充电和放电二进制变量使用储能 PCS 最大可建功率作为 Big-M 上界。

### 7.10 电池容量约束

对每个小时 `t`：

```text
storage_soc_t <= sum_i(q_bat_i * battery_capacity_i)
```

储能电量不能超过已建设电池总容量。

同时，电池组参数中的 `soc_upper` 和 `soc_lower` 会参与 SOC 许可逻辑：

- 当 SOC 不高于下限时，储能 PCS 不能放电。
- 当 SOC 不低于上限时，储能 PCS 不能充电。
- 构网储能的向上、向下调节能力也会被这两个阈值进一步限制。

### 7.11 电储能动态约束

当前程序从“规划参数”读取：

```text
eta_charge = storage_charge_efficiency
eta_discharge = storage_discharge_efficiency
s0 = initial_storage_soc_ratio
```

对 `t > 1`：

```text
storage_soc_t
- storage_soc_(t-1)
- eta_charge * storage_charge_t
+ storage_discharge_t / eta_discharge
= 0
```

对首小时：

```text
storage_soc_1
- eta_charge * storage_charge_1
+ storage_discharge_1 / eta_discharge
= s0 * sum_i(q_bat_i * battery_capacity_i)
```

含义：

- 初始电储能容量按规划参数 `initial_storage_soc_ratio` 处理，默认 0.5。
- 充电增加 SOC，放电降低 SOC。

### 7.12 电储能每日循环约束

对每天最后一个小时，即第 24、48、72 ... 8760 小时：

```text
storage_soc_day_end
= s0 * sum_i(q_bat_i * battery_capacity_i)
```

含义：

- 每天结束时电储能容量回到规划参数指定的初始 SOC。
- 因为下一天从上一天结束状态继续计算，所以等价于每天起始状态都回到该 SOC。

### 7.13 储氢容量约束

对每个小时 `t`：

```text
hydrogen_storage_t <= sum_i(q_ht_i * hydrogen_tank_capacity_i)
```

储氢量不能超过已建设储氢罐总容量。

### 7.14 氢储动态约束

当前程序从“规划参数”读取：

```text
h0 = initial_hydrogen_storage_ratio
```

对 `t > 1`：

```text
hydrogen_storage_t
- hydrogen_storage_(t-1)
- sum_i(electrolyzer_power_t_i * electric_to_hydrogen_efficiency_i)
+ sum_i(fuel_cell_power_t_i / hydrogen_to_electric_efficiency_i)
= 0
```

对首小时：

```text
hydrogen_storage_1
- sum_i(electrolyzer_power_1_i * electric_to_hydrogen_efficiency_i)
+ sum_i(fuel_cell_power_1_i / hydrogen_to_electric_efficiency_i)
= h0 * sum_i(q_ht_i * hydrogen_tank_capacity_i)
```

含义：

- 初始储氢量按规划参数 `initial_hydrogen_storage_ratio` 处理，默认 0.5。
- 电制氢增加储氢量。
- 燃料电池发电消耗储氢量。

### 7.15 氢储全年循环约束

对最后一个小时：

```text
hydrogen_storage_8760
= h0 * sum_i(q_ht_i * hydrogen_tank_capacity_i)
```

含义：

- 年末储氢量回到规划参数指定的初始 SOC 水平。
- 避免模型通过透支年末储氢来降低柴油消耗。

### 7.16 绿电电量占比约束

从“规划参数”读取：

```text
r = green_power_ratio_lower
```

当前程序定义：

```text
绿电年发电量 =
  sum_t(wind_power_t)
  + sum_t(pv_power_t)
  + sum_t(storage_discharge_t)
  + sum_t sum_i(fuel_cell_power_t_i)
```

```text
柴油年发电量 = sum_t sum_i(diesel_power_t_i)
```

```text
总发电量 = 绿电年发电量 + 柴油年发电量
```

约束为：

```text
绿电年发电量 >= 总发电量 * r
```

等价线性形式为：

```text
(1 - r) * 绿电年发电量 - r * 柴油年发电量 >= 0
```

程序在 MILP 中使用的是该线性形式。

### 7.17 非负约束和变量上界

所有运行变量均有非负下界。

部分运行变量还根据设备台数上限预设了求解变量上界，例如：

- 风电、光伏变量上界由设备最大建设台数下的最大可发功率决定。
- 储能充放电变量上界由储能 PCS 最大建设台数下的总功率决定。
- 储能 SOC 变量上界由电池最大建设台数下的总容量决定。
- 氢储变量上界由储氢罐最大建设台数下的总容量决定。

### 7.18 构网储能在线约束

对每个小时 `t`，如果某些储能 PCS 行设置了 `is_grid_forming = 1`，则这些行会引入台数级在线变量，并参与系统级在线约束：

```text
sum_i(diesel_on_count_t_i) + sum_j(grid_storage_on_count_t_j) >= 1
```

其中：

- `diesel_on_count_t_i`：第 `i` 行柴发开机台数
- `grid_storage_on_count_t_j`：第 `j` 行构网储能 PCS 在线台数

含义：

- 若系统中存在可用的柴发或构网储能，则每个小时至少要有一个可调电源在线。
- 这样可以保证后续的扰动后平衡约束有可用的调节资源。
- 变量规模与设备行数相关，不再与每行设备台数上限成倍增长。

### 7.19 扰动后平衡约束

当 `post_disturbance_power_balance_enabled = 1` 时，程序会对每个小时加入扰动后安全约束。

构网储能和柴发的系统向上调节能力定义为：

```text
系统向上调节能力
= 所有开机柴发的出力上限总和
  - 开机柴发实时出力总和
  + 构网型储能 PCS 容量总和
  - 构网型储能 PCS 实时净功率
```

其中“构网型储能 PCS 实时净功率”按放电为正、充电为负；跟网型储能 PCS 不参与电网向上/向下调节能力计算。

结果曲线中的系统向下调节能力按负方向显示，定义为：

```text
系统向下调节能力
= -1.0 * (
    所有开机柴发的实时出力总和
    + 构网型储能 PCS 实时净功率
    + 构网型储能 PCS 容量总和
  )
```

随后加入以下约束：

```text
系统向上调节能力 >= 负荷功率 * 负荷向上扰动系数
系统向上调节能力 >= 风光出力功率总和 * 新能源向下扰动系数
系统向上调节能力 >= 任意 1 台风光实时出力值
所有开机柴发的实时出力总和 + 构网型储能 PCS 实时净功率 + 构网型储能 PCS 容量总和
  >= 负荷功率 * 负荷向下扰动系数
```

含义：

- 当扰动后平衡开关打开时，模型不仅要满足正常功率平衡，还要保留一定的上下调节裕度。
- 上调节裕度主要用于应对负荷上升或新能源下降。
- 下调节裕度主要用于应对负荷下降。
- 如果储能电池 SOC 处于下限附近，则构网储能不具备向上调节能力；如果 SOC 处于上限附近，则构网储能不具备向下调节能力。

这些上界用于减少求解空间；真正的容量约束仍通过建设变量 `q_i` 线性约束实现。

## 9. 当前实现边界

以下内容是当前程序的实现边界，后续如需更精细模型可继续扩展。

1. 储能 PCS 和电池组按总容量聚合。
   当前约束分别使用总 PCS 功率和总电池容量，不强制某个 PCS 与某个电池组型号一一绑定。

2. 柴发和电制氢已按每台候选设备展开二进制启停变量。
   但同一设备行内各台设备仍共用该行的单台容量、上下限和效率参数。

3. 频率安全上下限、负荷扰动、N-1 等规划参数当前没有进入规划求解 MILP。
   当前规划求解输出的安全指标主要基于未供负荷和基础摘要。后续如需严格频率安全或 N-1 校核，需要新增对应线性或混合整数约束。

4. 日内电储能循环约束较严格。
   当前实现要求每天结束时 SOC 回到规划参数给定的初始电储 SOC，而不是只要求“当天起始 SOC 等于次日起始 SOC”的自由循环值。

5. 氢储只做全年循环。
   当前实现要求年末储氢量回到规划参数给定的初始氢储 SOC，没有要求每天循环。

6. 风电功率曲线使用当前 `estimate.wind_generation()` 近似模型。
   其中额定风速采用默认近似值，若后续需要厂家功率曲线，应替换该函数。

7. 光伏功率使用辐照度线性近似。
   当前公式按 `容量 * 太阳辐射 / 1000.0` 计算，并限制不超过装机容量。
